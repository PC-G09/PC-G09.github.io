Problem evolution

From scarce resources to weighted human capability.

The paper studies software projects in which activities are linked by precedence, people possess several skills, and proficiency differs by person and skill.

RCPSP

Resources + precedence

Schedule activities under renewable resource limits and dependency constraints.

→
MSRCPSP

Skills enter the model

Every task requires skills; every human resource masters one or more skills.

→
W-MSRCPSP

Proficiency is weighted

Skill proficiency is heterogeneous and represented by values in the interval [0, 1].

Paper Sections I and III

Related work and gap

Existing approaches solve parts of the problem, but leave two practical gaps.

Exact methods

MILP and mathematical programming

Can model multiple objectives and constraints, but become computationally demanding as problem size grows.

Heuristics

Priority and schedule-generation rules

Produce solutions quickly, but do not guarantee optimality and often simplify resource capability.

Metaheuristics

GA, PSO, VNS and related search

Explore large search spaces, yet many studies assume homogeneous proficiency or limited collaboration.

Gap 01Heterogeneous proficiency is often overlooked.
Gap 02Resources freed by unequal task durations may remain underused.

Paper Sections I–II

Research objective and contribution

Minimize makespan by making resource availability more intelligent.

01

Greedy best fit

Select the available resource with the highest matching skill proficiency.

02

Parallel task groups

Partition the precedence graph into dependency-safe subsets that can execute concurrently.

03

Surplus allocation

Assign spare resources to the latest-finishing scheduled task to reduce its finish time.

04

Freed-resource reuse

When the earliest task finishes, redirect its resources to remaining tasks in the same group.

Central claimBetter proficiency matching + less idle capacity = shorter project duration.

Notation verification

Three paper-level inconsistencies are explicitly controlled in this presentation.

01

dtᵢ: duration, not deadline

The problem-formulation paragraph calls dtᵢ a deadline, but Table 1, Equations (2), (7), (9), and the algorithm discussion use it as task duration. The slides use “duration.”

02

Constraint wording is separated from formula scope

Constraint (4) directly limits one skill contribution per resource for a given task. The broader “one task at a time” claim appears in prose and is not overstated as a standalone mathematical guarantee.

03

Figure references are corrected by captions

The results prose points to Figures 7 and 8 for Experiments 6 and 7. Their actual captions are Figure 8 (duration) and Figure 9 (resource demand), which this presentation follows.

Algorithm 1 · Top-level orchestrator

GPS builds parallel groups, schedules each group, and accumulates makespan.

  1. Create the array of dependency-safe task groups.
  2. Ignore groups containing dummy start or end tasks.
  3. Sort tasks in a group by finishing time.
  4. Call the subset scheduler and add its elapsed time.
Input T, S, R, EOutput project_makespan

Algorithm 2 · CreateParallelTasksGroups

Repeatedly extract vertices with no remaining predecessor.

  1. Scan the remaining task set.
  2. Select vertices that are not the right vertex of any remaining edge.
  3. Place them in the current parallel subset.
  4. Remove selected vertices and outgoing edges; repeat.
Input T, EOutput T∥[ ]

Algorithm 3 · ScheduleTasksSubset

The scheduler advances from one earliest-finish event to the next.

  1. Attempt an initial feasible assignment for unscheduled tasks.
  2. Use Algorithm 5 to place surplus capacity.
  3. Find the earliest-finishing task and release its resources.
  4. Update remaining effort and elapsed time for running tasks.
Input T∥, RavailOutput CT∥

Algorithm 4 · AssignResources

For each required skill, greedily choose the available resource with maximum proficiency.

  1. Visit every skill required by the task.
  2. Find the highest-weight available matching resource.
  3. Update task-skill finishing time after each assignment.
  4. Stop when the task can finish within dtᵢ; roll back if no match exists.
Input tᵢ, RavailOutput Boolean

Algorithm 5 · AssignExtraResources

Use spare capacity where it can reduce the group completion time most.

  1. Remove tasks that received no initial assignment.
  2. Select the latest-finishing scheduled task.
  3. Select that task’s latest-finishing skill.
  4. Assign any free resource possessing that skill; repeat.
Input T∥, RavailOutput surplus assignments

Synthesis of experimental evidence

GPS is strongest when the schedule contains exploitable flexibility.

Advantage expands when…

  • More resources are available.
  • Each task requires fewer skills.
  • Resource demand per task-skill is lower.
  • Graph complexity leaves more parallel tasks.
  • Task durations vary enough to release resources early.
Available flexibility→ GPS reallocation →Lower makespan

Advantage narrows when…

  • Skills consume most of the resource pool.
  • Mandatory headcount leaves little surplus.
  • Dense precedence relations suppress concurrency.
  • Few resources become free before the group completes.

Critical assessment

Promising simulation evidence, with a bounded validation scope.

Strength

Mechanism matches the problem

Weighted best fit and event-driven resource reuse directly target the two gaps identified by the authors.

Strength

Factor-by-factor analysis

Six sensitivity experiments explain the conditions under which the advantage expands or contracts.

Limitation

Simulation only

No industrial case study or real project dataset is reported.

Limitation

Primary comparison is PSS

The study does not establish superiority against a broad set of contemporary exact and metaheuristic methods.

Limitation

Model simplifications

Costs, uncertainty, skill evolution, switching, preemption and broader allocation constraints are outside the evaluated model.

Limitation

Notation and reporting ambiguity

Several formulas and result references need careful interpretation, as documented earlier in this presentation.

Conclusion

Use proficiency. Preserve parallelism. Reuse capacity.

GPS combines a greedy best-fit rule with parallel scheduling and repeatedly reassigns surplus or newly freed resources to reduce the latest finish time.

01

Heterogeneous skill weights produce more realistic resource selection than interchangeable-capacity assumptions.

02

The principal operational gain comes from keeping resources productive while parallel tasks finish at different times.

03

Across the reported simulations, GPS achieves a lower makespan than PSS in almost all tested settings.

Author-stated future workAdd more factors and constraints to resource allocation, and further improve the GPS method.
