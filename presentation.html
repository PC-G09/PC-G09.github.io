Problem evolution

From Resource-Constrained Scheduling to Weighted Multi-Skill Resources.

The paper models precedence-constrained software tasks performed by heterogeneous, multi-skilled human resources.

RCPSP

Resource Constraints + Precedence

Schedule project activities under limited renewable resources and task-dependency constraints.

→
MSRCPSP

Skill Requirements Are Added

Tasks require specific skills, while each human resource may master one or more skills.

→
W-MSRCPSP

Proficiency is weighted

Each resource–skill pair receives a proficiency weight in the interval \([0,1]\).

Related work and gap

Existing Approaches Address Key Dimensions, but Two Practical Gaps Remain.

Exact methods

MILP and Exact Optimization Models

Model multiple objectives, uncertainty, cost, risk, and quality, but become computationally expensive for large instances.

Heuristics

Priority and schedule-generation rules

Generate feasible schedules quickly, but may use simplified employee abilities, incomplete precedence modeling, or limited dynamic adaptation.

Metaheuristics

GA, PSO, VNS and related search

Explore complex search spaces effectively, but several studies still assume homogeneous proficiency, single-resource assignments, or simplified skill transitions.

Research objective and contribution

Minimizing Makespan Through Smarter Resource Allocation.

01

Greedy best fit

Select the available resource with the highest proficiency in each required skill.

02

Parallel task groups

Group precedence-compatible tasks into subsets that can execute concurrently when sufficient resources are available.

03

Surplus allocation

Assign surplus resources to the latest-finishing task and its latest-finishing skill.

04

Freed-resource reuse

When the earliest-finishing task completes, release and reassign its resources to the remaining tasks in the same parallel group.

Central claimWeighted skill matching and resource reuse reduce project makespan.

Model inputs and decision variable

Two matrices represent task requirements and heterogeneous resource proficiency.

Resource–Skill Matrix

\[RS=\begin{bmatrix}r_1s_1&r_1s_2&\cdots&r_1s_m\\r_2s_1&r_2s_2&\cdots&r_2s_m\\\vdots&\vdots&\ddots&\vdots\\r_ks_1&r_ks_2&\cdots&r_ks_m\end{bmatrix}\]

\(r_k s_j\in[0,1]\)

\[w_{r_k s_l t_i}=\begin{cases}1,&\text{if }r_k\text{ with }s_l\text{ is assigned to }t_i,\\0,&\text{otherwise.}\end{cases}\]

Feasibility condition: \(r_k\in R,\;t_i\in T,\;s_l\in S_{t_i}\cap S^{r_k}\).

Mathematical formulation · objective and constraints (2)–(4)

Minimize the Project Completion Time.

Objective (1)\[\min B_{t_{n+1}}\]

The start time of the dummy end task represents the project makespan.

(2)
\[B_{t_j}\ge B_{t_i}+d_{t_i},\qquad t_i,t_j\in T\land(t_i,t_j)\in E\]

A successor starts only after its predecessor finishes.

(3)
\[\sum_{r_k\in R_{s_l}}w_{r_k s_l t_i}=R_{t_i s_l},\qquad t_i\in T,\ s_l\in S_{t_i}\]

The number of assigned resources equals the resource requirement for each task–skill pair.

(4)
\[\sum_{s_l\in S^{r_k}\cap S_{t_i}}w_{r_k s_l t_i}\le 1,\qquad r_k\in R,\ t_i\in T\]

For a given task, one resource contributes through at most one skill.

Mathematical formulation · constraints (5)–(9)

Feasibility, non-negativity, compatibility and finish time.

(5)
\[\sum_{s_l=1}^{|S|} t_i s_l>0,\qquad \forall t_i\in T\land s_l\in S_{t_i}\]

Every project task requires at least one skill.

(6)
\[\sum_{r_k=1}^{|R|} t_i r_k>0\]

Intended meaning: at least one resource performs each project task.

(7)
\[B_{t_i}\ge0,\qquad d_{t_i}\ge0,\qquad \forall t_i\in T\]

Start times and durations are non-negative.

(8)
\[R_{t_i s_l}\subseteq\bigcup_{t_i r_k>0}S_{t_i},\qquad \forall t_i\in T\cap s_l\in S_{t_i}\]

Resources allocated to task \(t_i\) must possess the skills required to perform that task.

Model-reading note

Equations (6) and (8) are typographically ambiguous in the published paper. The interpretations shown here follow the accompanying prose.

Notation and reporting check

Three Notation and Reporting Ambiguities Are Handled Explicitly.

01

\(d_{t_i}\): Treated as Task Duration

The formulation initially calls \(d_{t_i}\) a deadline, while Table 1, Equations (2), (7), and (9), and the algorithm discussion use it as task duration. This presentation follows the latter interpretation.

02

Equation (4): Formula Scope vs. Prose

Equation (4) limits each resource to at most one skill for a given task. The broader “one task at a time” statement appears in the prose but is not explicitly represented by this equation alone.

03

Figure Numbers Follow the Actual Captions

The results prose refers to Figures 7 and 8 for Experiments 6 and 7. The corresponding plots are Figure 8 for task duration and Figure 9 for resource demand. This presentation uses the caption-based numbering.

Algorithm 1 · Top-Level Orchestrator

GPS Generates Parallel Task Groups, Schedules Each Group, and Accumulates Makespan.

  1. Generate the array of parallel executable task groups.
  2. Skip groups containing the dummy start or end task.
  3. Sort tasks by finishing time, earliest first.
  4. Schedule the selected group and add its completion time to the makespan.
Input \(T,S,R,E\)Output \(\mathrm{project\_makespan}\)

Algorithm 2 · Create Parallel Tasks Groups

Repeatedly Group Tasks with No Unresolved Predecessors.

  1. Scan all tasks remaining in \(T\).
  2. Select tasks that are not the right endpoint of any remaining precedence edge.
  3. Add all selected tasks to the current parallel group.
  4. Remove the selected tasks and their outgoing edges, then repeat.
Input \(T,E\)Output \(T_{\parallel}[\,]\)

Algorithm 3 · Schedule Tasks Subset

The Scheduler Advances from One Earliest-Completion Event to the Next.

  1. Assign resources to tasks that are unscheduled or do not satisfy the required time condition.
  2. Call Algorithm 5 to allocate any remaining resources to scheduled tasks.
  3. Identify the earliest-finishing task, mark it complete, and release its resources.
  4. Update completed effort and elapsed time for the remaining running tasks.
Input \(T_{\parallel},R_{\mathrm{avail}}\)Output \(C_{T_{\parallel}}\)

Algorithm 4 · Assign Resources

For Each Required Skill, Repeatedly Assign the Highest-Proficiency Available Resource.

  1. Process every skill required by task \(t_i\).
  2. Select the available resource with the highest proficiency in the current skill.
  3. Assign the resource and recompute the skill-specific finishing time.
  4. Continue until \(F_{t_i s_l}\le d_{t_i}\); if no matching resource exists, release the task’s assigned resources and return false.
Input \(t_i,R_{\mathrm{avail}}\)Output \(\mathrm{Boolean}\): true if successful, false otherwise

Algorithm 5 · AssignExtraResources

Assign Surplus Resources to the Latest-Finishing Task and Skill.

  1. Remove tasks that received no initial resource assignment.
  2. Select the latest-finishing task among the scheduled tasks.
  3. Identify the latest-finishing skill of the selected task.
  4. Assign a compatible available resource to that skill and repeat.
Input \(T_{\parallel},R_{\mathrm{avail}}\)Output Assignment of free resources to tasks in \(T_{\parallel}\)

Synthesis of experimental evidence

GPS is strongest when the schedule contains exploitable flexibility.

Advantage expands when…

  • More resources are available.
  • Each task requires fewer skills.
  • Resource demand per task-skill is lower.
  • Graph complexity leaves more parallel tasks.
  • Task durations vary enough to release resources early.
Available flexibility→GPSreallocation→Lower makespan

Advantage narrows when…

  • Skills consume most of the resource pool.
  • Mandatory headcount leaves little surplus.
  • Dense precedence relations suppress concurrency.
  • Few resources become free before the group completes.

Critical assessment

Promising simulation evidence, with a bounded validation scope.

Strength

Mechanism matches the problem

Weighted best fit and event-driven resource reuse directly target the two gaps identified by the authors.

Strength

Factor-by-factor analysis

Six sensitivity experiments explain the conditions under which the advantage expands or contracts.

Limitation

Simulation only

No industrial case study or real project dataset is reported.

Limitation

Primary comparison is PSS

The study does not establish superiority against a broad set of contemporary exact and metaheuristic methods.

Limitation

Model simplifications

Costs, uncertainty, skill evolution, switching, preemption and broader allocation constraints are outside the evaluated model. The paper also does not provide a formal computational-complexity analysis.

Limitation

Notation and reporting ambiguity

Several formulas and result references need careful interpretation, as documented earlier in this presentation.

Conclusion

Use proficiency. Preserve parallelism. Reuse capacity.

GPS combines a greedy best-fit rule with parallel scheduling and repeatedly reassigns surplus or newly freed resources to reduce the latest finish time.

01

Heterogeneous skill weights produce more realistic resource selection than interchangeable-capacity assumptions.

02

The principal operational gain comes from keeping resources productive while parallel tasks finish at different times.

03

Across the reported simulations, GPS achieves a lower makespan than PSS in almost all tested settings.

Author-stated future workAdd more factors and constraints to resource allocation, and further improve the GPS method.
